# Security policy and audit scope

RDU 0.3 provides explicitly confirmed permanent deletion to an ordinary-user metadata browser. Treat filenames, symlink targets, directory layouts, metadata, imported display data and terminal dimensions as untrusted. The selected root path is user input. The operating system, kernel filesystem ABI, libc and an uncompromised terminal emulator are trusted. The selected runtime has the static source coverage described below; this policy also states the limits of that coverage.

Security objectives are to avoid symlink traversal and file-content reads, avoid terminal escape injection from names, retain Rust memory safety around checked native parsing, bound workers/descriptors and retained entries, surface partial results, restore terminal state on handled exits, and permanently remove only independently reviewed live objects through protected slots. There is no product shell hook, network client/server or persistent privileged service. Offline/imported display data cannot mint deletion authority; a fresh live scan is required.

Child directories are opened using verified directory capabilities and `O_NOFOLLOW`, then matched to observed device/inode identity. Uncached paths are reopened component by component from the pinned root. A root ending in a symlink is refused after redundant trailing separators/dots are stripped. Ancestors of an explicitly supplied root can resolve symlinks, as in normal Unix path lookup. Pinned observed directories may move during a live scan. A directory identity check is not a filesystem snapshot or defense against a compromised kernel, malicious FUSE driver, inode reuse with matching identity, or authorized processes changing metadata during observation.

Native attribute buffers use aligned storage, checked slice reads, checked offset arithmetic, validity bits, checked NUL-terminated child names, and stat fallback for unsupported or nonregular metadata. Filesystem entries cannot inject terminal control sequences; non-UTF8 bytes and controls are displayed as visible escapes. The scanner never calls a shell or opens an entry for its contents.

## Deletion scope and trust boundary

Deletion is separated from scanning/rendering by `DeletionSession`, a fresh immutable review plan and a nonserializable, single-use `ConfirmedPlan`. A read-only request, incomplete/error/cancelled scan or imported tree provides no session. Root and setuid execution are refused. Staging performs metadata operations only: no rename, quarantine, journal, chmod/ACL change or unlink. A complete folder plan explicitly includes hidden and scan-excluded contents. Confirmation consumes the exact reviewed plan; cancellation, filtering, navigation, row reordering and a typed phrase by itself are not capabilities. The UI must keep session/tree generations together.

Permanent deletion requires local writable APFS with ownership enforcement, a trusted same-filesystem anchor outside the selection, verified root/ancestor identities and a fresh private quarantine. Only the newly created owned quarantine has its inherited ACL replaced and mode set to0700; privacy is read back before objects move. Nondirectory source opens additionally require a pinned current-UID-owned parent without group/other write and without allow ACL entries, or a narrowly verified trusted sticky-parent/current-UID-owned-object case. Unprovable/shared source namespaces preserve their files without opening them. Directories use `O_DIRECTORY|O_NOFOLLOW`; supported files/symlinks use `O_EVTONLY|O_SYMLINK|O_NONBLOCK|O_NOCTTY`. `O_EVTONLY` does not guarantee removal of read rights or safe arbitrary device opens. Production does not read file contents, and unsupported types are refused before a nondirectory open.

Each confirmed object is pinned, captured with atomic no-overwrite rename into its own immediate protected slot and checked against the retained handle before slot unlink/rmdir. Original mutable source names are never the final unlink namespace. Directories are processed bottom-up, including empty directories, using nonrecursive rmdir. Source substitutions, newly inserted children, occupied restoration names and unexpected quarantine occupants are preserved/restored without overwrite where possible and reported. There is no recursive quarantine cleanup or copy/delete fallback. The operation can partially complete; cancellation does not undo earlier purges.

The entire raw-component graph and all possible capture intents are journaled/fsynced before the first move; checked result appends and final flushes report failures. Append/flush failure stops admission, preserves recovery and does not promise a complete durable audit. Journals/imports are never restart deletion authority, and no automatic purge/resume exists. Allocation is not reclaimed space, secure erasure or a power-loss transaction. Counts cover all objects; bounded detail reports retain the journal when clipped.

This isolation excludes actively adversarial same-UID processes, root, compromised kernels/filesystem drivers and trusted owner processes undermining namespace permissions. A0700 directory cannot isolate two processes sharing a UID. An open writer may change a confirmed inode's bytes. Fresh size/time/birth metadata detects many changes but cannot universally prove absence of inode reuse before a transient live pin. Repeated ancestor checks cannot provide an atomic current-path containment guarantee. These limits must not be advertised away. See `docs/deletion.md`, `docs/next/deletion-service.md` and `docs/next/deletion-threat-review.md`.

Defaults cap workers at8, cache descriptors at16, retained entries at10million, and depth at1024. Configuration accepts1..64workers. Retained-tree memory grows with names; entry/depth caps are configurable. Resource exhaustion can still terminate an ordinary user process, and kernel/filesystem calls can block. Use an OS sandbox, restricted account, and suitable entry cap for hostile mounts. SIGKILL, terminal disappearance, and kernel failure cannot guarantee restoration; `stty sane` repairs ordinary terminal mode if needed.

Deletion separately caps one prepared basket at1million graph objects, relative depth1024 and approximately256MiB of allocation accounting, with bounded active descriptors. This is not a process RSS cap. Plans expire10minutes after preparation completes. Cooperative preparation/execution cancellation is checked between metadata/mutation steps; a kernel call already running cannot be forcibly recalled. Detailed reports are capped at4096 records/about8MiB, with complete aggregate counters and retained journal hints.

Validation includes exact metadata oracle fixtures, regular hardlinks, symlink loops and dangling links, denied directories, concurrent directory/symlink swaps, sparse attempts, resource forks, FIFO metadata, depth/entry bounds, malformed/randomized native records, terminal injection strings, resizing, and terminal restoration across handled exits. The report states what was source-reviewed and what was executed.

Deletion tests mutate only owned disposable fixtures. They exercise real APFS purge, symlinks/hardlinks, a240-level path under a64-FD subprocess limit,1024-file and4101-object closures, replacements at deterministic boundaries, retained-dirfd insertion, source ACL/mode gates, cancellation, expiry, occupied restoration, interrupted capture, journal append/flush failures and unexpected quarantine contents. Mount-policy negative tests use synthetic flag/type metadata. No actual foreign-account writer, privileged mount race, ownership-disabled real volume, device open, arbitrary power-loss event or broad OS certification was tested. Those gaps remain visible for the independent 0.3 audit.

Limitations: the third-party crate source and a fresh vulnerability-advisory database were not audited; no runtime sanitizers, coverage-guided fuzzer, privileged mount-race tests, true cold-cache tests, or broad OS/hardware certification were performed. A source audit with no outstanding validated findings does not establish that software is vulnerability-free.

## Reporting and review status

Report issues with the version, source/binary hash, OS/filesystem and a minimal synthetic reproduction. Do not include private filenames or user data. A public vulnerability-report endpoint is not configured.

The selected runtime is bound to its source in [the publication source manifest](evidence/publication/source-manifest.json). A Standard Codex Security source scan of `e591e3f1992fef70039dc5ea9b578c84d6aa3c93` completed with zero findings: 84 full-content reviewed files and 198 notice-only files, with all 282 classified and credential-reviewed. The selected simpler scanner is covered by a separate zero-finding static diff review of `e591e3f..ea5969853f52770e627dfb60333194a182f9edc2`.

Read the [Standard report](evidence/security/standard-report.md), [fallback diff report](evidence/security/fallback-report.md) and [transformation provenance](evidence/security/provenance.json) together. These are clearly labeled derived publication copies; authoritative sealed originals remain unchanged privately. Later result-documentation and final benchmark-helper revisions fall outside those immutable scan scopes; helper provenance is recorded separately in the performance manifest. These reviews do not certify the executable or establish that software is vulnerability-free. Product, deletion, terminal and packaging checks have separate receipts.

The optional `profile` Cargo feature and examples are developer diagnostics. Use one diagnostic scan at a time; concurrent resets/scans can mix telemetry. The normal CLI does not enable these diagnostics.
