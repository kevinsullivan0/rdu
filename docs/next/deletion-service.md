# Reviewed permanent deletion service

`src/delete.rs` exposes a live-scan session, an observational prepared plan, a single-use confirmed plan, cancellation controls and explicit outcomes. The macOS executor is in `src/delete/macos.rs`. This document describes the implemented contract; it is not the separate final Codex Security audit.

## Authority and review

`DeletionSession::scan(path, options, read_only)` returns a `Tree` and optional session. Read-only requests, incomplete/error/cancelled scans, root/setuid credentials and unsupported root policies cannot obtain a session. Imported trees cannot be passed to a session constructor. Returning to live operation requires a fresh live scan.

The wrapper first opens the normalized final root with `O_DIRECTORY | O_NOFOLLOW`, then resolves a separate canonical authority/review path. The live scan retains the caller's path spelling, consistently with read-only scans, so exact and regex filters and subsequent refreshes see the same spelling. The pinned original, canonical root and scanned root must have the same device/inode identity. Canonical `/private/tmp` review paths therefore support macOS's normal `/tmp` alias without making an unchecked pathname deletion authority. Subsequent authority traversal opens individual components without following links and checks captured identities.

`Target { directory, entry }` indexes the immutable bindings held by its session. The UI must keep its displayed tree and session in the same generation and discard them together on refresh. `prepare` processes the whole selected basket; overlapping targets collapse to their selected ancestor. It builds a fresh complete closure, including hidden and scan-excluded contents. It performs no mkdir, rename, permission/ACL change, journal write or unlink. Preparation reads directory listings and metadata, never file contents.

`prepare_with_control(targets, &PrepareControl)` checks cooperative cancellation through metadata traversal, entry enumeration, manifest construction and before returning authority. Cancellation returns `Interrupted`; partial preparation releases its handles and mints no plan. Kernel metadata calls and the bounded in-memory sort are not asynchronously interruptible. The UI must own and join a single cancelled preparation worker before launching its replacement.

The summary provides full selected-root paths, fresh object counts, observed allocation and scope notes. `manifest_path(index)` reconstructs exact individual paths on demand. Allocation is an observation, not reclaimed space: hardlinks, APFS clones, snapshots, open writers and concurrent allocation changes prevent that inference. A completed plan expires ten minutes after preparation finishes. Exact `DELETE <selected-root-count>` confirmation consumes the plan and creates a private, nonserializable Rust capability. Executing requires that capability; a phrase, imported snapshot or journal alone cannot execute.

## Metadata handles and source namespaces

Directories use `O_DIRECTORY | O_NOFOLLOW`. Nondirectories use `O_EVTONLY | O_SYMLINK | O_NONBLOCK | O_NOCTTY`. `O_SYMLINK` opens the final link itself; combining it with `O_NOFOLLOW` rejects links on the tested system. `O_EVTONLY` does **not** establish a descriptor without read capability. Production enforces the no-content-read property by never issuing a nondirectory read, write, mmap or content-copy operation. Apple's [open manual](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/man/man2/open.2) documents these flag distinctions.

`O_NONBLOCK` alone is insufficient protection against an arbitrary substituted device. XNU can call a device driver's open routine; FIFO open can wait for its counterpart without nonblocking mode. Therefore a nondirectory is inspected before opening and must be a regular file or symlink in a source namespace excluded writers cannot replace:

- The pinned parent belongs to the current UID, has no group/other write bits and has an empty or deny-only ACL; or
- The pinned parent belongs to root/current UID, has sticky-directory protection, the object belongs to the current UID, and the parent has an empty or deny-only ACL.

The policy is checked through the parent descriptor. Other cases are preserved without a nondirectory open. Shared writable or unprovable directories can consequently produce partial outcomes; no permission stripping or unsafe-open fallback is applied to user data. Directory handles remain type constrained, and nonempty directories receive no recursive purge fallback. The reasoning assumes trusted same-UID/root processes maintain namespace policy. Sources: XNU [open dispatch](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/vfs/vfs_syscalls.c), [FIFO open](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/miscfs/fifofs/fifo_vnops.c), and [device open](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/miscfs/specfs/spec_vnops.c).

## Protected capture and purge

Only local writable APFS with ownership enabled is admitted. Root ancestry must be root/current-UID owned and lack foreign write authority, except trusted root-owned sticky directories. The scan root is the quarantine anchor and cannot itself be selected. Its namespace must be current-UID owned and protected, or trusted root-owned sticky storage. The anchor is outside all selected subtrees.

After confirmation, the executor creates a fresh random child beneath that anchor. It verifies owner/identity, resets inherited ACLs **only on that new owned directory**, sets mode 0700, reads the ACL/mode back and checks the directory is empty before admitting objects. It never sanitizes user subtrees. Darwin ACL absence and end-of-entry conventions are handled explicitly; permission/unsupported failures fail closed. Apple's [ACL implementation](https://raw.githubusercontent.com/apple-oss-distributions/Libc/main/posix1e/acl_file.c) explains the file-security-property retrieval, and its [ACL entry manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/acl_get_entry.3.html) describes Darwin return values.

Each object is processed bottom-up. The executor reopens and checks its parent components, verifies its fresh metadata version, obtains a live object handle under the source policy above, and retains that handle through capture and purge. Files carry device/inode/type, birth time, size, modification/change times and link count. Directories use identity/birth checks during execution because deleting their confirmed children changes directory metadata. Hardlink change-time/link-count updates caused by RDU's own unlink are corroborated by the retained handle and applied only to the matching staged versions.

`renameatx_np(..., RENAME_EXCL)` captures each object into its own predeclared opaque component directly beneath the private parent. It never overwrites, copies across filesystems or falls back to direct source-name unlink. The captured identity is compared with the retained live handle. A mismatch is never purged: restoration uses another no-overwrite rename, and a re-created source name leaves the captured replacement preserved. Apple's [rename manual](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/man/man2/rename.2) distinguishes no-overwrite destinations from source substitution.

Only a verified immediate private slot is unlinked. Every confirmed directory, including an empty one, receives its own capture and nonrecursive `AT_REMOVEDIR`. A retained foreign descriptor into an original descendant cannot replace the protected slot. New children make rmdir fail; they survive in a restored or retained directory. Quarantine cleanup removes only the validated known journal and known empty directory. Unexpected occupants prevent cleanup. There is no `remove_dir_all` executor path.

## Journal, failures and recovery

Before the first move, a versioned journal records the raw-component parent graph, identities and **all** possible capture intents/opaque slots. The complete intent manifest, quarantine directory and anchor are fsynced before capture begins. Checked result records are appended as work proceeds and flushed at the end. Append failure stops further admission; captured objects remain and uncertainty is reported. Flush failure retains recovery storage and does not claim a complete durable audit. These steps do not form an atomic recursive transaction or promise arbitrary power-loss recovery; `fsync` is not Apple's stronger `F_FULLFSYNC` guarantee. See Apple's [fsync manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fsync.2.html).

Each complete JSON record plus newline is first serialized into a reusable buffer capped at64KiB, then appended with one checked `File::write_all`. This is one logical append rather than a promise of one physical syscall: short/interrupted writes can require retries. Oversized serialization fails before touching the destination. There is no cross-record buffering that defers an admission-related append error. Intent-manifest writing checks cancellation between records and before capture eligibility. A cancellation marker and its flush are checked; successful cancellation retains the verified owned recovery storage, reports every selected object as not attempted and performs zero captures. Marker write/flush errors remain I/O errors, even when cancellation is also requested. A partial intent journal is never resume authority.

Reports distinguish purged, restored, preserved, not attempted and uncertain outcomes. Cancellation prevents new admission and checks again before purge; a syscall already in progress may finish. It does not roll back earlier purges. Aggregate counts cover every object. Details are bounded to 4096 records/about 8 MiB; the full intent/result journal is retained when details are clipped. A journal is a reconciliation hint after restart, never a confirmation token, purge list or automatic-resume instruction. Restoration after restart requires independent live inspection and an explicit decision. Re-created names must never be overwritten.

After cancellation or an execution error, the remaining immutable manifest prefix is counted in bulk as not attempted. Only remaining visible detail slots reconstruct paths; hidden stopped objects do not each allocate a path or outcome string. A checked journal stop record identifies the remaining prefix, followed by the aggregate summary and final flush. Existing journal errors remain errors; later bookkeeping cannot turn an incomplete audit into a success. Releasing the retained in-memory manifest still takes work proportional to its allocations.

## Resource and trust limits

One prepared basket admits at most 1,000,000 graph objects, relative depth 1024 and an approximately 256 MiB conservative allocation-accounting budget. Names and parent indices replace full-path copies; active descriptor use does not grow with subtree width or depth. The budget is not a process RSS cap: retained scan trees, session bindings, allocator overhead and bounded result records are separate. Functional fixtures cover a 240-level path exceeding `PATH_MAX`, 256 sibling files and a 64-descriptor child-process limit, plus a 4101-object deletion with clipped details and exact aggregate/journal accounting.

Fresh metadata and review become authority after scan-time row identity checks. Without retaining millions of scan/plan descriptors, inode reuse before a transient live pin is not universally distinguishable; timestamps/birth identity improve detection but are not a mathematical ABA guarantee. Once pinned, that live object—not a later occupant of its old name—is admitted to purge. Concurrent ancestor renames cannot be excluded atomically by repeated checks. Detected changes retain recovery objects; the operation does not promise an atomic current-path containment transaction.

Isolation excludes an actively adversarial same-UID process, root, a compromised kernel/filesystem driver and owner processes that undermine the protected namespace policy. A same-UID process can access a 0700 directory. An already-open writer can change bytes of a confirmed inode after capture. There is no secure-erasure or fixed-reclaimed-space claim.

Tests use only owned disposable `/tmp/rdu-delete-disposable-*` fixtures. Deterministic tests cover source replacement between pin/capture, occupied restoration names, retained-dirfd insertion, ancestor movement, ACL setup/refusal, cancellation and expiry, interrupted capture, append/flush failures, unexpected quarantine occupants, and 24 isolated concurrent swap runs. Negative mount flags and device-shaped metadata are tested without opening devices. Actual foreign-account writers, privileged mount transitions, ownership-disabled real volumes and power-loss durability were **not** exercised; no helper account, mount, sudo operation or device fixture was created. These remain explicit validation gaps for the independent integrated audit.
